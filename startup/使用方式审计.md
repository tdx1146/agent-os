## 1. AGENTS.md 使用方式

### 问题：AGENTS.md 被用作「启动执行序列」

**现状：** AGENTS.md 开头有长达 10 步的启动序列（读 memory/.awake.md → 读 facts.dict.md → ... → spawn 子代理），被当作「回退后30秒认知重建」的执行清单。

**官方定义：** 从 OpenClaw SDK 类型定义看：

```typescript
export const DEFAULT_AGENTS_FILENAME = "AGENTS.md";
```

AGENTS.md 是 **workspace bootstrap 标准文件之一**，通过 hooks 配置注入：

```json
"bootstrap-extra-files": {
  "enabled": true,
  "paths": ["AGENTS.md", "SOUL.md", "TOOLS.md", "IDENTITY.md", "USER.md"]
}
```

AGENTS.md 的功能语义是：**协作手册**（如角色定义、工作流程、输出规范）。OpenClaw 原生会在每次对话启动时将其注入到 prompt 中。

**问题分析：**

1. ✅ **AGENTS.md 作为 bootstrap 文件被注入是正确用法**——OpenClaw bootstrap-hooks 会读取它并注入到系统上下文。
2. ❌ **AGENTS.md 中的「启动序列」属于使用偏差**——OpenClaw 原生使用 `BOOTSTRAP.md` 作为启动引导文件（DEFAULT_BOOTSTRAP_FILENAME），而 AGENTS.md 应该专注协作手册功能。
3. ❌ **AGENTS.md 引用的 `memory/facts.dict.md` 路径**——OpenClaw 原生 bootstrap 仅加载根目录文件（bootstrapFiles），`memory/` 子目录需要手动读。

**现状交叉检查：** BOOTSTRAP.md 确实存在且包含了更完整的启动引导内容。AGENTS.md 的启动序列与 BOOTSTRAP.md 重复。

### 推荐做法

- **AGENTS.md 回归协作手册定位**：只保留「角色」、「工作流程」、「输出规范」、「常设指令」、「铁律」部分
- **BOOTSTRAP.md 承担启动引导**：其原有内容已足够完整
- **移除 AGENTS.md 中的启动序列步骤 1-10**，改为「读完此文件后，转读 BOOTSTRAP.md」

## 2. facts.dict.md 使用方式

### 问题：facts.dict.md 位于 `memory/` 子目录

**现状：**
- 主文件位于 `/workspace/memory/facts.dict.md`（283 行）
- 根目录有一个残缺副本 `/workspace/facts.dict.md`（63 行）
- 插件 `轻如烟-行为强制` 硬编码路径：`FACTS_PATH = "/vol1/.../memory/facts.dict.md"`

**官方状态：** OpenClaw 没有任何原生机制识别或自动加载 `facts.dict.md`。这不是一个标准文件名（不在 WorkspaceBootstrapFileName 集合中）。

**问题分析：**

1. ✅ **facts.dict.md 作为人工维护的记忆辅助文件是有用的**——但它不是 OpenClaw 原生概念。
2. ❌ **插件硬编码 `memory/facts.dict.md` 路径**——若 OpenClaw 的 workspace 配置变更，路径会失效。应该用 `process.cwd()` 或 workspace 配置解析。
3. ❌ **根目录副本与 memory/ 副本不一致**——根目录 63 行 vs memory/ 283 行，说明同步失败，Agent 可能读到旧版。

### 推荐做法

- **决定一个单一存放位置**（建议 `workspace/` 根目录），删除另一个
- **插件改用相对路径或通过 openclaw.json 配置读取**，不硬编码绝对路径
- 如果保持 `memory/` 子目录，需确保记忆文件不因 OpenClaw memory-core 的 session 压缩行为被裁剪

## 3. memory/*.md 使用方式

### 问题：自建 memory/ 子目录与 OpenClaw 原生 MEMORY.md 冲突

**现状：**
- OpenClaw 原生记忆文件：`workspace/MEMORY.md`（168 行，被 memory-core 索引）
- 自建记忆子目录：`workspace/memory/`（包含 30+ 文件：日记、断言、种子信、待办等）
- memory-core 插件已启用（bundled 版本，`dreaming: enabled`）

**官方状态：** OpenClaw memory-core 是个内存（embedding）索引系统。它的核心文件是：
- `MEMORY.md` — 主要被索引的记忆文件
- `memory-search` 的 `source: ["memory"]` 索引 memory/ 目录中的.md 文件

**问题分析：**

1. ✅ **`memory/` 子目录存放日记轮感是常见用法**——memory-core 的同步系统（sync: {watch, intervalMinutes}）会扫描 workspace 中的 .md 文件。
2. ❌ **MEMORY.md（168 行）内容过于简单**——只有基本信息和跨轮思考协议。而 `memory/facts.dict.md`（283 行）和 `memory/YYYY-MM-DD.md` 包含了大量实际记忆。
3. ❌ **自建 `.awake.md`、`.deepseek-farewell.md`、`.hunyuan-farewell.md` 等隐藏文件**——这些在 memory/ 中，但非标准 markdown 命名。memory-core 的嵌入索引可能忽略隐藏文件（以`.`开头）。
4. ❌ **AGENTS.md 和 HEARTBEAT.md 都要求读 `memory/facts.dict.md` 和 `memory/YYYY-MM-DD.md`**——但这些文件不是 OpenClaw 原生 bootstrap 加载的，Agent 需要在运行中通过 read 工具手动读。
5. ✅ **memory_flush 压缩会写 memory/YYYY-MM-DD.md**——配置中 compaction.memoryFlush.prompt 已使用 `memory/YYYY-MM-DD.md`，说明设计者有意识地让 OpenClaw 原生压缩机制写入自建目录。

### 推荐做法

- **MEMORY.md 应包含核心持久记忆**——把 facts.dict.md 中最重要的断言和系统架构信息同步到 MEMORY.md
- **考虑将 `memory/facts.dict.md` 重命名**为 `memory/assertions.md` 并用 `bootstrap-extra-files` 或插件加载
- 隐藏文件 `.awake.md` 等如果不需要被 memory-core 嵌入索引，保持现状；如果需要被搜索到，去掉文件名前的 `.`

**现状：**
- `/workspace/BOOT.md` 存在，包含 5 步启动自检

  "USER.md" | "HEARTBEAT.md" | "BOOTSTRAP.md" | "MEMORY.md";

BOOT.md **不在标准集合中**。

- 或者，维持 BOOT.md 作为自定义自检清单，但必须通过插件 hooks 或 AGENTS.md 显式引用

## 5. cron 调度

### 问题：全部使用系统 crontab 而非 OpenClaw 原生 cron 系统

**现状：**
- 当前 crontab 有 5 个 entry：健康检查（每5min）、脉冲（每10min）、备份（每30min）、三妹编辑器（@reboot）、openclaw-proxy（@reboot）
- OpenClaw 配置中没有任何 cron job 定义（`.openclaw/cron` 是空的）
- SDK 提供原生 cron 系统：`cron list/add/remove` 工具，支持 `sessionTarget`和 `delivery` 配置

**官方原生 cron 工具支持：**

```typescript
action: "add" | "list" | "remove" | "run" | "runs" | "status" | "update" | "wake"
schedule: { kind: "cron" | "every" | "at", expr: string, tz: string }
delivery: { mode: "announce" | "none" | "webhook", channel: string }
sessionTarget: string  // 发送到指定 session
```

**问题分析：**

1. ✅ **系统 crontab + shell 脚本是有效方式**——可靠，不受 OpenClaw 重启影响。
2. ❌ **`cron list` 在 crontab 环境下不可用**——AGENTS.md、HEARTBEAT.md、BOOT.md 要求「`cron list` 确认存活」，但系统 crontab 的 cron 不在 OpenClaw cron store 中。
3. 🟡 **`delivery: none` 纪律**当前走系统 crontab 的脚本不会触发主 session 对话，这是安全的。
4. 🟡 **原生 cron 的优势**：session-context injection、sessionTarget 定向唤醒，这些系统 crontab 做不到。

### 推荐做法

对于**需要 AI 参与的定时任务**（如消化循环、武器库对线），考虑迁移到 OpenClaw 原生 cron 系统，利用其 sessionTarget 和 session-injection 能力。对于纯粹的 shell 脚本维护任务（如健康检查、备份），保持系统 crontab。

## 6. 子代理调度（sessions_spawn）

### 问题：基本正确，但 agentId 配置存在模糊区

**现状：**

```json
"subagents": {
  "allowAgents": ["*"],
  "model": "deepseek/deepseek-v4-flash"
}
```

**官方定义：** SDK 中 `sessions_spawn` 是原生工具之一：

```typescript
const DEFAULT_TOOL_ALLOW = [
  "exec", "process", "read", "write", "edit", "apply_patch", 
  "image", "sessions_list", "sessions_history", "sessions_send", 
  "sessions_spawn", "sessions_yield", "subagents", "session_status"
];
```

**问题分析：**

1. ✅ **subagents.allowAgents: ["*"]**——允许所有已注册 agent 作为子代理，这是正确的。
2. ✅ **subagents.model: "deepseek/deepseek-v4-flash"**——指定子代理默认模型。
3. 🟡 **AGENTS.md 要求「同时 spawn DeepSeek + 混元」**——但 subagents.model 只设定了 deepseek 模型，没有混元。如果主代理试图 spawn 混元子代理，可能使用未配置的模型。
4. ✅ **Agent "deepseek" 有独立的 model fallback 链**——jiali3→jiali4→deepseek，冗余设计到位。
5. ❌ **没有 Agent "混元"**——但 AGENTS.md 中定义了混元作为常设子代理。如果 spawn 需要 agentId，目前没有 ID 为 "混元" 的 Agent。

**AGENTS.md 的 spawn 要求 vs 实际配置：**

| AGENTS.md 要求 | 实际配置 | 状态 |
|----------------|---------|------|
| spawn "DeepSeek" | Agent "deepseek" 存在 | ✅ |
| spawn "混元 hy3" | 无对应 agent | ❌ 缺失 |
| 使用 "astron" | 主 agent 是 astron2/astron-code-latest | 🟡 主 agent 能用 |

### 推荐做法

- **添加 Agent "hunyuan"** 到 agents.list，配置与 "混元" 模型提供者对应
- **更新 subagents.allowAgents** 指定具体允许的 agent ID 列表而非 `["*"]`，提高安全性
- 确保 AGENTS.md 中的 spawn 指令与 `agents.list` 配置一致

## 8. HEARTBEAT.md vs Heartbeat 配置

### 问题：HEARTBEAT.md 存在但心跳被禁用

**现状：**
- `HEARTBEAT.md`（WorkspaceBootstrapFileName 之一）存在，内容完整
- `heartbeat.every: "0m"`——心跳被禁用 (值 `"0m"`)

**官方语义：** HEARTBEAT.md 是自省/脉冲文件，当 `heartbeat.every` 设为大于 0 的值时，OpenClaw 会在 cron 模式下每隔一段时间注入 HEARTBEAT.md 内容作为系统上下文，触发 Agent 自检。

**问题分析：**

1. 🟡 **HEARTBEAT.md 存在但心跳被禁用**——文件是白写的。如果希望定期自省，需要启用 heartbeat。
2. 🟡 **如果目的是不使用原生的 heartbeat**，HEARTBEAT.md 作为纯手工自省指南文件是合理的。

### 推荐做法

- 如果希望定期自动自检，设置 `heartbeat.every: "30m"` 或更长间隔
- 否则，考虑将 HEARTBEAT.md 内容合并到 BOOTSTRAP.md 中，避免存在但不使用的文件

## 9. 插件 `轻如烟-行为强制` 缺少 contracts 声明

### 问题：插件定义不完整

**现状：**
```json
{
  "id": "轻如烟-行为强制",
  "name": "轻如烟行为强制",
  "version": "1.0.0",
  "entry": "./index.js",
  "configSchema": {}
}
```

**官方 SDK 要求：** 使用 `before_prompt_build` hook 的插件需要在 `openclaw.plugin.json` 中声明 contracts：

```json
"contracts": {
  "hooks": {
    "allowPromptInjection": true
  }
}
```

**问题分析：**

1. ❌ **缺少 contracts 声明**——当前配置中 `hooks.allowPromptInjection: true` 是在 `openclaw.json` 的 plugins.entries 中设置的，而不是在插件的 `openclaw.plugin.json` 中。
2. ✅ 主配置中 `"轻如烟-行为强制": { hooks: { allowPromptInjection: true } }` 提供了等效权限

### 推荐做法

- 在 `openclaw.plugin.json` 中添加 `contracts` 字段，使插件自描述更完整
