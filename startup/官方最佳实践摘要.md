## 一、设计哲学

### 1.1 OpenClaw 的核心定位

| 维度 | 官方描述 | 备注 |
|------|---------|------|
| 本质 | **多通道 Gateway**，不是 AI 框架 | 一条 Gateway 进程 = Discord/Telegram/WhatsApp/WebChat 等所有通道的网桥 |
| 控制面 | WS 协议（端口 18789）管理 | 所有 client/node 通过 WS 连接 |
| 记忆 | **纯 Markdown 文件**，无隐藏状态 | "The model only remembers what gets saved to disk" |
| 一致性 | session per-sender 序列化 | 工具调用/会话历史一条写锁保护 |

### 1.2 推荐使用方式

- **一个 Gateway 管所有通道**，不要多开 Gateway
- **BOOT.md 是钩子**（hooks internal），不是自检脚本集合
- **AGENTS.md 是协作手册**（给 AI 看怎么调度），不是系统配置
- **SOUL.md 是角色人格**，不要在里面放路径或配置
- **MEMORY.md 是精选长期记忆**，不是日志存档
- **memory/*.md 是日常工作层**，自动索引，按需读取
- **系统 prompt 是 OpenClaw 拥有的**，不要通过 `before_prompt_build` 大量改写

## 二、记忆系统官方实现

### 2.1 三层模型

```
MEMORY.md              → 长期记忆，每次 DM 会话加载
memory/YYYY-MM-DD.md   → 每日笔记，今日+昨日自动加载
memory/.dreams/        → 梦境工作层（机器状态）
DREAMS.md              → 梦境日记（人类阅读）
```

**关键规则**：
- `MEMORY.md` 必须在 `bootstrapMaxChars`（默认 20000）内，超限截断 *但不丢文件*，仅注入副本截断
- `memory/*.md` **不属于**普通 turn 的 bootstrap Project Context。日常 turn 通过 `memory_search` / `memory_get` 按需读取
- 只有在 `/new` 或 `/reset` 时，OpenClaw 才将最近每日记忆作为一次性的 startup context 注入

### 2.2 官方索引机制

- 默认 backend：**SQLite (FTS5 + sqlite-vec)**
- 索引内容：`MEMORY.md` + `memory/*.md`
- 索引方式：~400 token 分块，80 token 重叠
- 文件变化后 1.5s 防抖自动重索引
- 切换 embedding provider 自动重建索引

### 2.3 memory-core 插件提供的工具

| 工具 | 说明 |
|------|------|
| `memory_search` | 混合搜索（向量+关键词），通过 embedding provider |
| `memory_get` | 读特定文件/行范围 |

### 2.4 `memory_search` vs 嵌入搜索

- `memory_search` 搜**自己索引过的内存文件**（MEMORY.md + memory/*.md）
- 它不搜索 workspace 任意文件，不搜索外部目录（除非配 `extraPaths`）
- 当 embedding provider 不可用时，降级到 FTS-only 关键词搜索

### 2.5 Dreaming 系统

- **默认关闭**，需在 `plugins.entries.memory-core.config.dreaming` 开启
- 三阶段：Light（短信号分拣）→ Deep（评分+晋升到 MEMORY.md）→ REM（模式提取）
- 输出到 `DREAMS.md`（人类阅读）和 `memory/.dreams/`（机器状态）
- 晋升门槛：`minScore` + `minRecallCount` + `minUniqueQueries`

## 三、Bootstrap 注入机制

### 3.1 默认注入文件清单

| 文件 | 状态 | 用途 |
|------|------|------|
| `AGENTS.md` | ✅ 注入 | 协作手册 |
| `SOUL.md` | ✅ 注入 | 人格指南 |
| `TOOLS.md` | ✅ 注入 | 本地笔记/环境 |
| `IDENTITY.md` | ✅ 注入 | 身份 |
| `USER.md` | ✅ 注入 | 用户信息 |
| `HEARTBEAT.md` | ✅ 条件注入 | 仅心跳启用时 |
| `BOOTSTRAP.md` | ✅ 仅首次 | 首次工作空间 |
| `MEMORY.md` | ✅ 注入 | 长期记忆（当 present） |

### 3.2 注入控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `bootstrapMaxChars` | 20000 | 单文件上限 |
| `bootstrapTotalMaxChars` | 60000 | 总上限 |
| `contextInjection` | `always` | 可选 `continuation-skip` / `never` |
| `bootstrapPromptTruncationWarning` | `always` | 截断时是否通知模型 |

### 3.3 推荐用法

- 保持注入文件**精简**，超过限制会被截断
- `TOOLS.md` 经常超限——官方说这是正常的，用 `/context list` 监控 raw vs injected
- 使用 `contextInjection: "continuation-skip"` 在连续回合中减少重复注入
- **memory/*.md 每日文件不在 bootstrap 里**（除了 `/new` `/reset`），用工具按需读

### 3.4 Hook 扩展点

`agent:bootstrap` 钩子可在注入前拦截/替换文件（例如动态切换 SOUL.md 人格）

## 四、Compaction 官方最佳实践

### 4.1 机制

| 特性 | 说明 |
|------|------|
| 触发 | 接近 context 限制 或 context overflow error 时自动触发 |
| 手动 | `/compact` / `/compact 关注主题` |
| 内存刷写 | compaction 前自动运行**一次 silent turn** 提醒模型存笔记 |
| 模式 | `default`（合并）或 `safeguard`（分块摘要） |
| 后继转录 | `truncateAfterCompaction` 创建更小的新 JSONL |

### 4.2 关键配置

```json5
{
  compaction: {
    mode: "safeguard",
    keepRecentTokens: 50000,  // 保留最近的 tokens
    identifierPolicy: "strict",  // 保留标识符（ID/编号）
    memoryFlush: {
      enabled: true,
      model: "ollama/qwen3:8b",  // 可选本地模型刷写
    },
    truncateAfterCompaction: true,  // 轮转转录文件
    maxActiveTranscriptBytes: "20mb", // 本地转录体积触发
  }
}
```

### 4.3 内存刷写设计意图

> 这是官方**最重要的一个设计决策**：

- compaction 前会自动跑一个 silent model 调用，存未保存的笔记到 `memory/YYYY-MM-DD.md`
- 这不是可选的——要禁用它才需要明确设置
- **compaction 本身不是数据丢失**，完整历史仍在磁盘（JSONL），compaction 只改变模型"看到"的上下文
- 通过 `/status` 可看到 compaction 计数

### 4.4 分离 Compaction 模型

```json5
{
  "compaction": {
    "model": "ollama/llama3.1:8b"  // 用本地模型做摘要，保留主力模型做回复
  }
}
```

## 五、多代理配置官方规范

### 5.1 结构

```json5
{
  agents: {
    defaults: { /* 共享默认值 */ },
    list: [
      { id: "main", default: true, workspace: "..." },
      { id: "work", workspace: "..." }
    ]
  },
  bindings: [
    { agentId: "home", match: { channel: "whatsapp", accountId: "personal" } }
  ]
}
```

### 5.2 继承规则

- `agents.list[].skills` 省略则继承 `agents.defaults.skills`
- `agents.list[].skills: []` = 无技能
- `agents.list[].skills: ["docs-search"]` = **替代**默认，不合并

### 5.3 Subagent 调度

- `subagents.allowAgents`：可 spawn 的 agent 白名单（`["*"]` = 允许全部）
- `subagents.requireAgentId`：强制指定 agent（防止默认误调度）
- **promptMode: "minimal"** 是子代理的官方 system prompt 模式
  - 仅注入 AGENTS.md 和 TOOLS.md
  - 过滤掉 SOUL.md/IDENTITY.md/USER.md/MEMORY.md——保持子代理上下文小

## 六、与当前实现的对比及偏差

### ❌ 偏差 1：记忆存储路径错误（严重）

| | 官方推荐 | 当前实现 |
|--|---------|---------|
| MEMORY.md | workspace 根目录 | 使用自定义路径"所有自动化/轻如烟/" |
| memory/ | workspace/memory/ | 使用自定义路径 |

**问题**：官方 `memory_search` / `memory_get` 默认只索引 `workspace/MEMORY.md` + `workspace/memory/*.md`。我们把记忆文件放在 `所有自动化/轻如烟/memory/` 但 `memory_search` 搜的是 workspace。

**建议**：
- ✅ 把 `MEMORY.md` 移回 `workspace/`（使用 symlink 或 cp）
- ✅ 把 `memory/` 目录也通过 `extraPaths` 或 symlink 纳入索引
- 或者通过 `memorySearch.extraPaths` 配置额外路径

### ❌ 偏差 2：Bootstrap 文件过大（中）

| 标准 | 官方默认 | 当前 |
|-----|---------|------|
| bootstrapMaxChars | 20000 | 可能超出（TOOLS.md 含大量工具列表） |
| bootstrapTotalMaxChars | 60000 | 可能超出 |

**问题**：`AGENTS.md` + `TOOLS.md` + `系统启动能力清单.md`（105行）等大量文件同时注入，容易超限被截断。**截断不是数据丢失**但可能导致模型"看不到"重要指令。

**建议**：
- 将 `系统启动能力清单.md` 从固定 bootstrap 移除，改为通过 `memory_get` 按需读取
- 配置 `contextInjection: "continuation-skip"` 减少重复注入
- 用 `/context list` 监控实际注入大小

### ❌ 偏差 3：compaction.memoryFlush 被禁用（严重）

| | 官方推荐 | 当前 |
|--|---------|------|
| compaction.memoryFlush | `enabled: true`（默认） | ✅ 已禁用（写入 facts.dict.md 作为系统状态） |

**问题**：facts.dict.md 里写 `compaction.memoryFlush: ❌ 已禁用（由6h cron替代）`。但 cron 和 memoryFlush 不是替代关系——memoryFlush 是 compaction **之前**的现场笔记保存，cron 是定期总结。如果用户聊到关键时刻 compaction 触发，但没有 memoryFlush 保存当前上下文，已存到 session 但未存到 memory 的笔记可能丢失。

**建议**：
- 重新启用 `compaction.memoryFlush.enabled: true`
- 如果担心 token 消耗，设置 `memoryFlush.model: "ollama/qwen3:8b"` 用本地模型
- 保持 6h cron 作为补充（不同的正交维度）

### ❌ 偏差 4：使用 memory_search 但 embedding 已损坏（中）

| | 官方推荐 | 当前 |
|--|---------|------|
| memory_search | 向量+关键词混合 | ❌ 向量部分不可用，降级到 FTS-only |

**建议**：
- 修复 embedding provider（配置 OpenAI/Gemini/Ollama embedding）
- 或明确设为 `provider: "none"` 让 FTS 成为有意选择而非故障状态

### ❌ 偏差 5：BOOT.md 使用方式偏离（轻微）

| | 官方设计 | 当前 |
|--|---------|------|
| BOOT.md | hooks internal 的自检钩子 | 被作为 AGENTS.md 的启动序列引用 |

官方说 BOOT.md **是钩子注册的入口**，不应放入 AGENTS.md 的工作流中作为"步骤"。如果 gateway 启用了 `hooks.internal.enabled`，BOOT.md 应由钩子系统自动运行，不需要 AI 显式检查。

### ✅ 符合最佳实践的做法

| 实践 | 状态 |
|------|------|
| AGENTS.md 作为协作手册 | ✅ |
| 使用 `sessions_spawn` 作为子代理调度 | ✅ |
| 技能系统（skill workshop） | ✅ |
| 三套搜索体系分离（MCP 各自独立） | ✅，但 memory_search 应与 dandan-embedding 协调 |
| 日记在 memory/ 目录 | ⚠️ 路径路径不对（见偏差 1） |
| cron 调度行为 | ✅ 轻量，delivery:none |
| edit-web.py 编辑器独立进程 | ✅ |
| 子代理 promptMode minimal（非 full） | ✅ |

## 七、健康巡盘结果

### 7.1 明确需要修的

1. **记忆路径错位** — 将 MEMORY.md 和 memory/ 纳入 workspace 索引范围
2. **重新启用 compaction.memoryFlush** — 配上本地模型
3. **修复或确认 memory_search 的 embedding 状态**

### 7.2 可以优化的

4. 启用 `contextInjection: "continuation-skip"` 减少 token
5. 减少 bootstrap 文件总大小（将大摘要移至按需读取）
6. 考虑启用 `dreaming` 做自动记忆晋升

### 7.3 不应改的

- 三套搜索体系并行 ✅ 设计合理，各司其职
- sandglass 作为独立记忆层 ✅ 补充而非替代 memory_search
- cron 调度纪律 ✅ 符合官方推荐

## 八、快速修复命令集

```bash
# 1. 检查 memory_search 状态
openclaw memory status --deep --agent main

# 2. 如果 embedding 不可用，强制重建索引
openclaw memory index --force --agent main

# 3. 检查 bootstrap 注入大小
# 在 WebChat 或控制 UI 中运行
/context list

# 4. 添加 memory 额外路径（如果 memory/ 不在 workspace）

# agents.defaults.memorySearch.extraPaths 添加 "所有自动化/轻如烟/memory"

# 5. 重新启用 compaction.memoryFlush
```
