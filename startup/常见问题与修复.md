## 一、失忆相关问题

### 1.1 会话截断失忆（postCompactionSections）

**根因**：OpenClaw 的 `compaction.postCompactionSections` 机制会在压缩后只保留 AGENTS.md 中的指定 section。

- **配置位置**：openclaw.json → `agents.defaults.compaction.postCompactionSections`
- **当前值**：`["启动", "铁律"]`
- **问题机制**：
  1. AI 输出内容太长 → 触发压缩
  2. 压缩后上下文只保留 AGENTS.md 的「启动」和「铁律」section
  3. 其他全部丢失 → AI 失忆

**影响范围**：所有的编译压缩都会触发这种「部分失忆」

**已采取的预防措施**：
1. AGENTS.md 的启动区块可恢复关键信息（推荐！）
2. memory_flush 的 memory_dump 脚本定期备份上下文
3. 轮感日记（memory/YYYY-MM-DD.md）每 6 小时自动记录

**如果失忆了**：
1. 去翻 session transcripts：
   ```bash
   ls -lt ~/.openclaw/agents/main/sessions/*.jsonl | head -10
   ```
2. 找到失忆前的 session 文件（看 mtime）
3. 读取 `.jsonl` 中的对话内容
4. 从轮感日记恢复上下文

### 1.2 Cron 失忆事故（2026-06-28）

**根因**：`AI群聊项目-PDCA检查` cron 配置 `sessionTarget: "session:global"`，每 5 分钟创建新 session 覆盖主对话。

**症状**：
- 用户正在对话 → AI 突然失忆，不认识之前说的任何事
- Session transcript 文件被新 session 覆盖
- 上下文彻底消失

**修复**：
- `sessionTarget` 改为 `isolated`

**教训**：
- **所有 cron 任务必须用 `sessionTarget: isolated` 或 `current`**
- **禁止使用 `sessionTarget: session:xxx` 或 `main`**
- **用户活跃对话期间，cron 不应打断主 session**

**验证方法**：
```bash
# 检查所有 cron 任务的 sessionTarget
cat ~/.openclaw/cron/jobs.json.migrated | grep -A 3 sessionTarget
# 应全部显示 "isolated" 或 "current"
# 不应出现 "main" 或 "session:global"
```

## 二、插件相关问题

### 2.1 插件热重启杀 session（2026-06-14）

**根因**：发送两次 SIGUSR1 → 第二次 = forced restart = 杀 session。

**铁律**：
| # | 规则 |
|---|------|
| PLUGIN-01 | 改完插件只发一次 SIGUSR1，禁止连击 |
| PLUGIN-02 | SIGUSR1 前确认 session 空闲（无 pending 模型调用） |
| PLUGIN-03 | 用 inject-helper 发真实文本触发插件，空消息不触发 |
| PLUGIN-04 | gateway tool restart 走进程自重启，优先 systemd |
| PLUGIN-05 | 重加载后验证注入标记（`/tmp/last-injection-body.txt` mtime） |

### 2.2 插件注入不生效

**检查清单**：
1. 插件文件是否存在：
   ```bash
   ls -la ~/.openclaw/plugins/轻如烟-行为强制/
   ```
2. openclaw.json 配置是否正确：
   ```bash
   cat ~/.openclaw/openclaw.json | grep -A 5 "轻如烟-行为强制"
   ```
3. 插件运行时标记：
   ```bash
   cat /tmp/plugin-ran.txt
   ```
4. 重启 Gateway 后验证：
   ```bash
   # 检查日志是否有插件加载信息
   tail -20 /vol1/@apphome/trim.openclaw/data/logs/openclaw.log | grep plugin
   ```

### 2.3 我的 index.js 在哪里？

行为强制插件路径：
```

```

sandglass-logger 插件路径：

## 三、搜索相关问题

### 3.1 搜索工具缺失

**症状**：MCP 工具列表中看不到 web_search、embedding_search 等

**检查**：
1. dandan-mcp-server.mjs 是否存在：
   ```bash
   ls -lh ~/openclaw/data/workspace/dandan-mcp-server.mjs
   ```
2. openclaw.json MCP 配置：
   ```bash
   cat ~/.openclaw/openclaw.json | grep -A 5 '"dandan"'
   ```
3. 是否注册成功（重启 Gateway）：
   ```bash
   openclaw gateway restart
   ```

### 3.2 内存搜索无效（向量搜索失效）

**状态**：已知问题，不会修复

**原因**：NAS CPU-only，batch 超时。向量索引不重建。

**替代方案**：
- 用 BM25 搜索（dandan MCP 的 `embedding_search`）
- 用 FTS 全文搜索（memory_search 的 fallback）
- 上述两种已满足日常使用需求

### 3.3 TTS 不可用

**检查**：
```bash
curl -s --max-time 10 -X POST -H "Content-Type: application/json" \
  -d '{"text":"test","voice":"zh-CN-XiaoxiaoNeural"}' \
  http://127.0.0.1:18888/api/tts
```

**失败处理**：
1. edit-web.py 是否在运行（端口 18888）
2. router.py 中 `/api/tts` 路由是否存在
3. edge-tts 是否安装（`pip list | grep edge-tts`）

```bash
# 等待 5 秒预热后再发送请求
```
