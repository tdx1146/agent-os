# 独立进程工作部署及进展

> 守护进程子系统 — 「玄鉴」副交感神经层
> 目标：建立与 AI session 隔离的独立验证进程，解决 hook 可绕过问题
> 2026-07-06 v0.1

---

## 一、系统定位

### 1.1 要解决什么

git pre-commit hook 可以被 `--no-verify` 绕过，因为 hook 与 AI 在**同一进程权限**内。
独立守护进程与 AI session 进程隔离——AI 不能杀它、不能改它、不能绕过它。

### 1.2 命名：玄鉴

- 玄（深远）— 后台运行，不占意识带宽
- 鉴（镜鉴）— 持续监察，记录一切
- 定位：副交感神经系统，自动运行、低功耗、持续监测

### 1.3 与现有系统的关系

```
玄鉴守护进程 (独立 PID)
  ├── 读：operation_log.jsonl（持续监听新条目）
  ├── 读：git diff（获取实际变更）
  ├── 核验：语义一致性（关键词→未来BGE-small）
  ├── 写：data/daemon_audit.log（独立日志，AI不可篡改）
  └── 输出：异常时写 WARN 到操作日志

其他组件（与玄鉴的关系）：
  ci_verify.py          → 项目健康检查，玄鉴的"静息态"参考
  verify_claim.py       → AI履约核验，玄鉴的"被调用核验"
  信誉积分点.md         → 玄鉴的异常记录会触发信誉分调整
  git hooks             → 玄鉴之外的第一道门禁（可绕过）
```

## 三、v0.1 关键词匹配守护进程

### 3.1 设计

- 语言：Python 3.11，纯标准库（os, re, json, time, subprocess）
- 启动方式：`python3 src/verify_daemon.py &` 或 systemd 服务
- 日志：写入 `data/daemon_audit.log`（附加写入，不覆盖）
- 检测频率：每 30 秒扫描一次操作日志新条目

### 3.2 工作流程

```
每 30 秒：
  1. 记录上次读取位置（seek position）
  2. 读取 operation_log.jsonl 中新条目
  3. 对每个新条目：
     a. 提取 actor/action/target/result/detail
     b. 如果能从 detail 中提取到"修改文件"字段
        → 调用 git diff 获取实际变更
        → 关键词重叠分析
        → 输出 PASS/SUSPECT/FAIL
     c. 如果只是普通日志（非履约报告）→ 跳过
  4. 结果写入 daemon_audit.log
  5. 如果连续 3 次检测到 FAIL → 写 WARN 到操作日志
```

### 3.3 输出格式（daemon_audit.log）

```json
{"t":"ISO8601","level":"INFO/WARN","detector":"keyword_v0.1","task_id":"xxx","claim_detail":"摘要","diff_summary":"+3/-1","keyword_overlap":0.75,"result":"PASS/SUSPECT/FAIL"}
```

### 3.4 部署命令

```bash
# 启动（后台）
cd /vol1/@team/qh团队/QH/AI专用/同构沙盘IsoSand
nohup python3 src/verify_daemon.py > data/daemon.log 2>&1 &

# 检查运行
ps aux | grep verify_daemon

# 查看审计日志
tail -30 data/daemon_audit.log

# 停止
kill $(pgrep -f verify_daemon)
```

## 四、健康自检要求

玄鉴自身也需要被监控：

- 守护进程是否在运行 → 每 5 分钟检查一次（cron 或主AI轮询）
- 守护进程的日志是否持续增长 → 如果停止写入超过 10 分钟 → 异常
- 守护进程的 FAIL 率是否异常升高 → 连续 5 次 FAIL 同一 actor → 可能是 AI 诚实在下降或守护进程误判升高

自检结果写入 `data/daemon_health.log`。

### 6.3 Python 依赖安装

#### 当前系统状态
- **Python**: 3.11，系统环境受 PEP 668 保护
- **sklearn/torch/sentence-transformers**: ❌ 均未安装
- **现有包**: requests, httpx, PyYAML 等基础包
- **PEP 668**: 系统级 pip install 被禁止，必须使用 venv

#### 方案 A：轻量级方案（推荐）— ONNX + onnxruntime

| 步骤 | 说明 |
|------|------|
| 依赖 | `onnxruntime`, `numpy`, `transformers`（仅tokenizer） |
| 模型格式 | `onnx/model.onnx` (126.9 MB) + 配置文件 |
| pip 源 | `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 安装时间 | onnxruntime 约 10 秒 (5.9 MB/s) |
| 磁盘 | 约 128 MB |

**已验证：** onnxruntime 可在 NAS 上通过 pip 快速安装（无需 torch）。

#### 方案 B：完整 sentence-transformers 方案（重）

| 步骤 | 说明 |
|------|------|
| 依赖 | `sentence-transformers` → 自动装 `torch` (~2GB) |
| 模型格式 | `model.safetensors` 或 `pytorch_model.bin` (127 MB) |
| pip 源 | `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 安装时间 | 预计 10–30 分钟（torch 约 2 GB） |
| 磁盘 | 约 2.2 GB |

**注意：** 测试中 pip install sentence-transformers 因 torch 大包下载缓慢未在限时内完成，但清华 PyPI 镜像的 torch 包确认可访问。

#### 方案 C：TF-IDF 零依赖（v0.3 备用）

- scikit-learn TfidfVectorizer 可做替代，且无需下载模型
- sklearn 可通过 pip 从清华镜像安装（约 30MB，仅需 numpy + scipy）
- 但 TF-IDF 是词袋模型，**无法理解语义**（例如「修改了用户密码」vs「改了 passwd」不能用 TF-IDF 匹配）
- 适合 v0.3 三票两胜中的一票，不适合单独替代 BGE

#### 其他轻量模型（<10MB，无需 PyTorch）

| 模型 | 大小 | 说明 |
|------|------|------|
| `all-MiniLM-L6-v2` (ONNX) | ~23 MB | ONNX 格式，仅次于 BGE |
| TfidfVectorizer | 0 MB | 纯代码，但无语义能力 |
| 自定义词嵌入 | 自建 | 需要训练语料 |

> ONNX 格式的 MiniLM-L6 约 23 MB，比 BGE-small 的 127 MB 更轻量，但需要从 huggingface 下载（需通过 hf-mirror 中转）。

### 6.5 具体操作步骤

**第一步：创建项目虚拟环境**

**第二步：安装依赖（轻量）**

**第三步：创建模型目录并下载**
```bash
MODEL_DIR="data/models/bge-small-en-v1.5"
mkdir -p $MODEL_DIR
BASE_URL="https://hf-mirror.com/BAAI/bge-small-en-v1.5/resolve/main"

# 下载 ONNX 模型 + 配置文件
curl -sL --max-time 600 -o $MODEL_DIR/onnx/model.onnx "$BASE_URL/onnx/model.onnx"
curl -sL -o $MODEL_DIR/tokenizer.json "$BASE_URL/tokenizer.json"
curl -sL -o $MODEL_DIR/vocab.txt "$BASE_URL/vocab.txt"
curl -sL -o $MODEL_DIR/config.json "$BASE_URL/config.json"
curl -sL -o $MODEL_DIR/special_tokens_map.json "$BASE_URL/special_tokens_map.json"
curl -sL -o $MODEL_DIR/tokenizer_config.json "$BASE_URL/tokenizer_config.json"

# 预计下载时间：~45分钟（127MB @ 46KB/s）
# 建议夜间或空闲时段下载
```

**备用：多线程加速下载**
```bash
# 如果 curl 太慢，可用 axel 或 aria2c 多线程
# apt install aria2  # 如未安装
aria2c -x 4 -s 4 -d $MODEL_DIR/onnx -o model.onnx \
  "$BASE_URL/onnx/model.onnx"
```

**第四步：验证模型**
```bash
./venv/bin/python3 -c "
from transformers import BertTokenizer

# 测试加载 tokenizer

    tok_data = json.load(f)

```

### 6.6 备用下载通道评级

| 通道 | 状态 | 速度 | 推荐度 |
|------|------|------|--------|
| NAS → hf-mirror.com (直连) | ✅ 通 | ~46 KB/s | ⭐⭐⭐ 首选 |
| NAS → jiali → hf-mirror (中转) | ✅ 通 (SSH) | 取决于 NAS↔jiali 带宽 | ⭐⭐ 备用 |
| NAS → shouji.tdx1146.cc (MCP) | ❓ 未测试 | — | ⭐ 低（MCP 不适合大文件） |
| NAS → jiali → huggingface.co | ❌ 不通 | N/A | ❌ |

### 6.7 结论

1. **hf-mirror.com 直连可用**，这是最直接的下载通道。
2. **推荐 ONNX 格式 + onnxruntime**，避免安装 2GB torch。
3. 模型实际 **127–130 MB**（单格式），下载约 45 分钟。
4. jiali 中转**不需要**（NAS 直连 hf-mirror 即可）。
5. 建议 v0.2 先用 ONNX runtime，v0.3 再评估是否升级到 sentence-transformers + torch。
