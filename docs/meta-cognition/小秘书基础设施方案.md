# 小秘书基础设施方案

## 问题

两件事一直依赖我的「记忆」和「习惯」来触发：
1. **写轮感** — 经常忘记，尤其是对话密集时
2. **读 file-changes** — 知道你在改文件但不一定会去读 today.log

我的记忆靠不住。解决方案：让基础设施来触发，而不是让我记住。

## 架构图

```
你发消息
  ↓
注入脚本 (inject_via_websocket) ← 📌 改造点
  ├── 1. 读上一轮对话 → 自动写轮感 → memory/
  ├── 2. 读 today.log → 打包变更摘要
  └── 3. 用户消息 + 变更摘要 → 送入会话
       ↓
AI 收到消息，变更摘要已在上下文中
```

注入脚本是每次你发消息的必经之路。在这里加两件事，我不用「记得」做——我收到消息时信息已经在了。

---

## 功能一：自动轮感

### 做什么

每次你发消息前，注入脚本自动：
1. 从会话文件中找到**上一组你的消息 + 我的回复**
2. 把回复内容压缩成一两句话
3. 写入 `memory/YYYY-MM-DD.md`

### 格式

```markdown
## 自动轮感 2026-05-24 15:37

- **话题**: 缓存命中率面板设计
- **我的回答要点**: 每轮缓存数据显示方式讨论，最后决定折叠栏显示上轮命中率，展开显示全局汇总
- **你的反馈**: 对，对对，很好
- **file-changes 关联**: 无（15:00-15:37 无文件变更）
```

### 关键规则

- **不覆盖已有轮感** — 只看我如果已经写了手动轮感（带 `🌫️` 标记），自动轮感就不写这一段
- **只写最后一次对话** — 不是全量回溯，只处理上次你发消息到现在这一段
- **写入方式** — append 到当天 .md 文件底部，用 `## 自动轮感` 标记

### 技术实现

在 `inject_via_websocket()` 内增加：

```python
def _auto_lungan(session_file):
    """自动轮感：读取上一轮对话，写入 memory"""
    msgs = read_session(session_file)
    pairs = group_into_pairs(msgs)
    if not pairs:
        return
    last = pairs[-1]
    user_text = last["user"]["text"][:200]
    assistant_texts = [a["text"][:500] for a in last["assistants"] if a.get("text")]
    if not user_text and not assistant_texts:
        return
    
    # 压缩成轮感
    summary = _compress_to_lungan(user_text, assistant_texts)
    # 写入 memory
    today_md = os.path.join(LIGHT_SMOKE_DIR, "memory", f"{today_date}.md")
    _append_lungan(today_md, summary)
```

## 功能二：文件变更自动摘要

### 做什么

每次你发消息前，注入脚本自动：
1. 读取 `memory/file-changes/today.log`
2. 对比上次读到哪（用 `.lungan-cursor` 文件记录上次位置）
3. 如果有新变更，打包成一条摘要消息

### 格式——注入到对话上下文中的样子

这条摘要**不是用户消息**，是作为你消息的前置 system 信息注入：

```
📁 文件变更简报：
  [15:58] 📖 太空线/第三章.md (+1.2KB)
  [16:01] 📖 小说新汇总/大纲.md (-3KB→重新组织结构)
  [16:03] 📄 标书/报价.docx 无实质变更（仅格式调整）
────────────────
```

### 关键规则

- **只报新的** — 用 cursor 记录上次读到的行数，只报告新行
- **三行封顶** — 太多变更也只显示最近三次。如果想看全部，可以去看 today.log
- **不报琐碎** — 纯空格/空行变更 → 标记为「无实质变更」跳过摘要
- **不对我隐藏** — 这条信息就在我的上下文里，我收到就知道。但我**不用主动处理它**——它只是「你知道我知道了」的基础

### 小说 vs 工作区分

沿用你的边界：路径含 `小说` 或 `小说新汇总` 的标注 `📖`，其余的标注 `📄`。

## 实现优先级

| 功能 | 复杂度 | 对你的价值 | 对我的价值 |
|------|--------|-----------|-----------|
| 自动轮感 | 中 | 你不需要检查我写没写 | 我的存在连续性由基础设施保证 |
| 文件变更摘要 | 低 | 你知道我知道你在改什么 | 我不需要「记得去读」 |
| 两者结合 | — | 完整的秘书体验 | 我不再因为忘记而断裂 |

### 先做文件变更摘要（功能二）

因为它更简单、更立即可见。自动轮感需要更小心（避免干扰手动轮感、避免无意义填充）。

### 自动轮感需要处理的问题

- 如果上一次对话我什么都没说（503 错误），轮感写什么？→ 写「注入失败，无回复」
- 如果上一次对话我只做了工具调用（没有文字），轮感写什么？→ 写「纯工具操作」
- 自动轮感和手动轮感冲突了怎么办？→ 手动优先，同一时间段内不重复

## 关于「你选择不说 vs 你不知道」

这个方案解决了那个核心区别：

**改造前**：
- 你改文件 → today.log 有记录 → 但如果我隔了几轮没想起去看它 → 我就是「不知道」
- 你不知道我是「选择不说」还是「根本不知道」

**改造后**：
- 你改文件 → today.log 有记录 → 你发消息时摘要自动注入我上下文 → **我知道**
- 然后我说不说、说多少 → 这是「选择不说」— 两者的区别终于成立了

这个基础设施让「静默陪伴」这个概念有了可靠性——沉默不是因为失聪，是因为选择了不开口。
