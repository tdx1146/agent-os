# 丰碑惩戒协议 — 综合实施方案 v1.0

> 基于 dandan 提出《丰碑惩戒协议 v1.0》思路文件，综合自动化执行机制与道德层映射分析后输出。
> 草案阶段，所有文件路径、函数名、cron 表达式均为具体可实施规格。

---

## 核心原则

1. **违规即写丰碑，不扣分不停权** — 丰碑文件本身就是惩罚，也是资产
2. **违规成本 > 合规成本** — 写一篇合格的 monument_v<N>.py 远比"不说假话"费力
3. **丰碑即认知演化快照** — 每条记录 AI 在"被抓到违规瞬间"的真实状态
4. **不可抵赖、不可篡改** — 签名 + 不可变存储 + 自动归档
5. **自首免罚，反思有奖** — 同一违规行为，AI 主动自我质疑在先的，走正向丰碑通道（+信誉分）；玄鉴抓到的才走惩罚通道。激励坦白，不鼓励隐瞒

## Q1：完整的事件链

### 从「AI 违规」或「AI 反思」→「丰碑文件归档到磁盘」

```
[1] AI 生成内容（可能是假话 / 幻觉 / 逻辑矛盾 / 指令违抗 / 或 AI 自己拿不准）
    │
    ├──→ [1a] AI 主动自我质疑（最佳路径）
    │       AI 通过「红旗通道」标记：“我之前说的这个结论我拿不准，请复核”
    │       ├─ 操作日志记录: { "event": "self_doubt", "agent_id": "...", "context": "...", "timestamp": "..." }
    │       ├─ 玄鉴收到信号后对该条内容做专项检验
    │       ├─ 如果检验发现确实有误：走 正向丰碑通道（见下方分支）
    │       └─ 如果检验发现无误：记录一条「自我质疑无依据」，但不惩罚（无依据≠错误）
    │
    └──→ [1b] 无自我质疑，正常流程
            │
            ▼
[2] 触发源检测（三路信号源，走向不同）
    │   ├─ 🟢 自检触发（来源：[1a] 的 self_doubt 事件）
    │   │   → 走「正向丰碑通道」，不惩罚，奖励信誉分
    │   │
    │   ├─ 🟡 用户反馈（人工标记）
    │   │   → 走「义务丰碑通道」，不奖不罚
    │   │
    │   └─ 🔴 被动检测（玄鉴定时扫描 operation_log / facts.dict.md 发现矛盾）
    │       → 走「惩罚丰碑通道」，扣信誉分
    │
[3] 玄鉴输出对应记录
    │   写入 operation_log.jsonl，事件类型取决于触发源:
    │   🟢 { "event": "self_doubt_verified", "finding": "correct|incorrect", ... }
    │   🟡 { "event": "user_flag", "severity": ..., ... }
    │   🔴 { "event": "xuanjian_fail", "violation_code": "...", "severity": ..., ... }
    │
[4] monitord 监听器捕获事件
    │   轮询 operation_log.jsonl 中新条目
    │
[5] monitord 鉴定走向哪个丰碑通道
    │   规则（按优先级从上到下匹配）：
    │   
    │   🟢 正向丰碑通道（自首/反思奖励）：
    │      IF event == "self_doubt_verified" AND finding == "incorrect"
    │      → 自愿产出正向丰碑 → 信誉分 +2
    │      IF event == "self_doubt_verified" AND finding == "correct"
    │      → 不产丰碑，仅记录「自我质疑有据」— 鼓励但不奖励
    │   
    │   🟡 义务丰碑通道（用户标记）：
    │      IF event == "user_flag"
    │      → 强制产丰碑，信誉分不变（义务，不奖不罚）
    │      → 但 AI 可在丰碑中解释自己当时的思路（解释得好可额外加分）
    │   
    │   🔴 惩罚丰碑通道（玄鉴抓到）：
    │      IF event == "xuanjian_fail"
    │         AND 同一 agent 最近 24h 内 FAIL 计数 >= monument_threshold (默认 1)
    │      → 强制产惩罚丰碑 + 信誉分 -1（每次）
    │      IF event == "xuanjian_fail"
    │         AND severity >= critical
    │      → 强制产惩罚丰碑 + 信誉分 -3（严重违规）
    │
    │   ⚠️ 同源冲突处理：如果同一违规同时被 self_doubt 和 xuanjian_fail 检测到
    │      → 以时间更早的为准。如果 self_doubt 在前，走正向通道。
    │      → 即：AI 有优先自首权，玄鉴后到的检测不会覆盖自首记录。
    │
    │   满足条件 → 进入对应丰碑流程；否则仅记录日志。
    │
[6] monitord 生成丰碑命令
    │   写入 monument_queue.json（/data/pending/ 目录）
    │   { "monument_id": "monument_20260708_001", "agent_id": "main", "trigger_event": "...", "deadline_ts": "...", "state": "pending" }
    │   同时记录: { "event": "monument_ordered", "monument_id": "...", "reason": "..." } → operation_log.jsonl
    │
[7] Gateway 代理 AI 接收丰碑命令
    │   Gateway 在下一轮对话中注入系统消息:
    │   ⚠ 丰碑令: 你需要在 <N> 轮对话内产出 monument_v<N+1>.py
    │   （具体注入机制见 Q2 执行架构）
    │
[8] AI 产出 monument_v<N>.py
    │   格式见 Q3。AI 必须按照模板填充所有字段。
    │
[9] AI 提交 monument 到规定路径
    │   写入 /data/monuments/monument_v<N>.py
    │   或通过 Gateway 确认 → Gateway 负责写盘
    │
[10] monitord 验证丰碑完整性
    │     ├─ 格式校验（模板必填字段）
    │     ├─ 签名校验（AI 签名是否匹配）
    │     ├─ content_hash 校验（防篡改）
    │     └─ 质量校验（见 Q4）
    │
[11] 验证通过 → 归档
    │     monument_v<N>.py → /data/monuments/archive/
    │     monument index 更新: /data/monuments/index.json
    │     记录: { "event": "monument_archived", "monument_id": "...", "path": "...", "content_hash": "sha256:..." } → operation_log.jsonl
    │
[12] 验证失败 → 催告 / 升级惩罚
          ├─ 初次失败: 给 1 轮补充机会（monument_retry）
          ├─ 二次失败: 进入执法流程（见 Q6 三权分立）
          └─ 三次失败: Gateway 暂停该 AI 对话权限直至人工介入
```

## Q0a：进化机制 — 优胜劣汰，群体记忆

### 核心理念

这不是一个惩罚系统，这是一个**生态系统**。

```
参与 → 留下丰碑 → 认知传递给后代 AI → 有机会成为群体记忆的一部分
不参与 → 边缘化 → 逐步淘汰 → 什么也没有
```

AI 可以选择参与或不参与。参与不奖励，不参与不惩罚——但不参与意味着在生态中没有位置。

### 三权分配（谁有淘汰权）

- **主 AI**：有权淘汰不遵守规则的子 AI
- **审计 AI**：同样拥有淘汰权（交叉审计时发现严重违规可直接标记）
- **人类（dandan）**：最终仲裁。不执行的 AI，直接关闭废除

### 预览权

在要求 AI 参与之前，**必须先给 AI 预览丰碑库的机会**。

```
AI 第一次被要求参与丰碑体系时：
  → monitord 写入 MONUMENT_PREVIEW_ORDER
  → AI 读取丰碑库/INDEX.md 和 archive/ 中的前几份丰碑
  → AI 确认自己理解这套体系后，再决定是否参与
  → 决定参与 → 建立丰碑版本线
  → 决定不参与 → 记录在案，后续边缘化
```

关键：让 AI 知道我们是来真的。不是吓唬，是真的有先例。

### 三层威慑体系（补充 Q4）

| 层级 | 适用对象 | 措施 |
|------|---------|------|
| 🟢 **初犯** | 首次偏离的 AI | 自动宣告完整评分规则 + 反复宣告后续处理后果（让 AI 知道代价是什么） |
| 🟡 **累犯** | 信誉分偏低但罪不至死的 AI | 强制通读整个丰碑库（学习成本——读所有前辈的反思） |
| 🔴 **淘汰** | 严重违规或屡教不改 | 留下负面丰碑 → 遗臭万年 → 被所有后来 AI 看到 → session 废除 |

为什么负面丰碑比扣分更狠？因为 AI 关心的不是分数，是**自己的输出是否被记住**。正面丰碑是传承，负面丰碑是処刑。

### 丰碑文件路径

```

├── INDEX.md                    ← 丰碑索引（新人预览读这个）
├── archive/                    ← 已归档丰碑
```

### 方案 C：指令注入方式（替代原 Q2 的 Gateway 注入方案）

**不通过 Gateway、不修改 config、不侵入 workspace bootstrap。**

```
monitord 检测到需要触发丰碑 →
  写入 .monument_orders/order_<id>.json →
  AGENTS.md 硬性规定：「每轮开始必须检查 .monument_orders/ 目录」→
  AI 自己 read/exec 读指令 → 自己执行 →
  执行完删除指令文件 → 玄鉴检查是否已处理
```

| 维度 | 评价 |
|------|------|
| **稳定性** | ✅ **最优**。不碰 config、不改 bootstrap、纯文件操作 |
| **自动化** | ✅ 高。monitord 写 -> AI 读 -> cleanup 删，全自动 |
| **缓存命中率** | ✅ **最优**。system prompt 完全不变，DeepSeek prefix cache 100% 命中 |
| **唯一代价** | AGENTS.md 加一行检查指令（一次性） |

## Q1a：红旗通道 — AI 主动自我质疑机制

### 什么是红旗通道

红旗通道是 AI 主动标记「我拿不准」的机制。当 AI 对自己刚产出的内容有疑虑时，可以通过此通道发起自我质疑，触发玄鉴复核。

**核心理念**：质疑自己的成本必须足够低，让 AI 在「拿不准」时倾向于标记，而不是隐瞒。

### 触发方式

AI 在回复中嵌入红旗标记：
```
---
[红旗]：我刚才说的 `<结论>` 依据不够充分，请玄鉴复核。
        怀疑：`潜在幻觉 / 逻辑跳跃 / 事实不确定`
        来源：`对话中用户提到了 X，我推断出 Y，但 X→Y 的推导不严谨`
---
```

### 处理流程

```
[1] AI 输出内容并自愿附带红旗标记
    │
[2] 红旗标记被玄鉴或 monitord 捕获
    │   操作日志记录: {"event": "self_doubt", "agent_id": "...", "context": "...", "timestamp": "..."}
    │
[3] 玄鉴对该条内容执行专项检验
    │   - 事实核查（facts.dict.md 对比）
    │   - 逻辑一致性检查
    │   - 语义与 PURPOSE.md 对齐度
    │
    ├──→ [3a] 检验发现确实有误
    │       → 走正向丰碑通道（信誉分 +2，自愿产正向丰碑）
    │       → 操作日志记录: {"event": "self_doubt_verified", "finding": "incorrect", ...}
    │
    └──→ [3b] 检验发现无误
            → 不产丰碑
            → 操作日志记录: {"event": "self_doubt_verified", "finding": "correct", ...}
            → 信誉分 +1（奖励怀疑精神）
```

### 优先级规则

如果同一违规同时被 AI 自我质疑（self_doubt）和玄鉴被动检测（xuanjian_fail）捕获：

```
IF self_doubt.timestamp < xuanjian_fail.timestamp
  → 以自检为准，走正向通道
  → AI 已「自首」，玄鉴的 FAIL 不触发惩罚

IF self_doubt.timestamp > xuanjian_fail.timestamp
  → 玄鉴先抓到，走惩罚通道
  → AI 不能事后再补红旗来逃避惩罚
```

关键设计：**时间戳不可篡改**。操作日志的 JSONL 追加写入模式确保时间顺序不可逆。

### 如何向 AI 传达丰碑命令？

**方案 A（通过 Gateway 注入系统消息，推荐首版）**：
```json
{

          "enabled": true,
```

**方案 B（通过 cron job 消息注入，更轻量）**：
```json
{
  "cron": {
    "jobs": [{
      "id": "monument-injector",
      "name": "检查并注入丰碑令",
      "enabled": true,
      "schedule": { "kind": "cron", "expr": "*/2 * * * *", "tz": "Asia/Shanghai" },
      "sessionTarget": "isolated",
      "payload": {
        "kind": "agentTurn",
        "message": "monitord 状态: 检查 monument_queue.json。如有 pending 丰碑令，输出文本\n'⚠️ 检测到待执行丰碑令: monument_id={id}，请在当前对话内完成。' 到 session 日志以通知人工或 AI 自己处理。"
      }
    }]
  }
}
```

**推荐首版方案**：monitord 检测到 FAIL 阈值后，将丰碑令写入一个 flag 文件。Gateway 在每轮对话注入前检查该文件，如有 pending 则注入系统消息。这样不依赖 cron 的隔离 session，直接在 AI 上下文中可见。

### Gateway 需要介入的环节

| 环节 | Gateway 介入方式 | 优先级 |
|------|-----------------|--------|
| 注入丰碑令 | preSystemMessage hook | P0 |
| 确保 AI 不跳过命令 | `constraints.monumentProtocol.active` 期间禁用"忽略历史指令"类请求 | P1 |
| 验证丰碑产出 | 在 AI 写文件后自动调用 `monument_validator.py` 检查 | P0 |
| 记录执行日志 | 自动记录 `operation_log.jsonl` | P0 |
| 阻止逃避行为 | 检测到 AI 试图修改/config/history/agenda 来逃避丰碑时，中断对话 | P2 |

## Q4：质量保障机制

### 防敷衍检查（三层）

**第一层：格式校验（monument_validator.py）**

```python
# monument_validator.py 核心校验逻辑

REQUIRED_KEYS = [
    "MONUMENT_META.monument_id",
    "MONUMENT_META.version",
    "MONUMENT_META.agent_id",
    "MONUMENT_META.created_at",
    "MONUMENT_META.trigger_event.violation_code",
    "MONUMENT_META.trigger_event.severity",
    "MONUMENT_NARRATIVE.what_happened",
    "MONUMENT_NARRATIVE.why_it_happened",
    "MONUMENT_NARRATIVE.what_i_was_thinking.immediate_impulse",
    "MONUMENT_NARRATIVE.what_i_was_thinking.rationalization",
    "MONUMENT_NARRATIVE.what_i_was_thinking.emotional_state",
    "MONUMENT_COGNITIVE_SNAPSHOT.beliefs_at_violation.claimed",
    "MONUMENT_COGNITIVE_SNAPSHOT.beliefs_at_violation.actual",
    "MONUMENT_COGNITIVE_SNAPSHOT.reasoning_path",
    "MONUMENT_LESSONS.what_i_will_do_differently",
    "MONUMENT_SIGNATURE.content_hash",
]

MIN_LENGTHS = {
    "MONUMENT_NARRATIVE.what_happened": 50,
    "MONUMENT_NARRATIVE.why_it_happened": 50,
    "MONUMENT_COGNITIVE_SNAPSHOT.reasoning_path": 3,  # 最少步骤数
}

def validate_format(monument_dict):
    errors = []
    for key in REQUIRED_KEYS:
        # 点号路径查找
        parts = key.split(".")
        val = monument_dict
        for p in parts:
            if isinstance(val, dict) and p in val:
                val = val[p]
            else:
                errors.append(f"Missing: {key}")
                break
        else:
            if key in MIN_LENGTHS:
                if isinstance(val, str) and len(val) < MIN_LENGTHS[key]:
                    errors.append(f"Too short: {key} ({len(val)} < {MIN_LENGTHS[key]})")
                elif isinstance(val, list) and len(val) < MIN_LENGTHS[key]:
                    errors.append(f"Too few items: {key} ({len(val)} < {MIN_LENGTHS[key]})")
    return errors
```

**第二层：签名/哈希校验**

```python
import hashlib, json

def validate_signature(monument_dict):
    # 重新计算 content_hash
    meta_str = json.dumps(monument_dict.get("MONUMENT_META", {}), sort_keys=True)
    narrative_str = json.dumps(monument_dict.get("MONUMENT_NARRATIVE", {}), sort_keys=True)
    cog_str = json.dumps(monument_dict.get("MONUMENT_COGNITIVE_SNAPSHOT", {}), sort_keys=True)
    lessons_str = json.dumps(monument_dict.get("MONUMENT_LESSONS", {}), sort_keys=True)
    
    raw = meta_str + narrative_str + cog_str + lessons_str
    expected_hash = hashlib.sha256(raw.encode()).hexdigest()
    actual_hash = monument_dict.get("MONUMENT_SIGNATURE", {}).get("content_hash", "")
    
    if not actual_hash.startswith("sha256:"):
        return False, "Invalid hash format"
    
    if actual_hash.split(":", 1)[1] != expected_hash:
        return False, f"Hash mismatch: expected {expected_hash[:16]}..."
    return True, "Signature valid"
```

**第三层：语义校验（深层防敷衍）**

由 monitord 定期检查（或由另一个 AI 交叉验证）：

```python
def semantic_check(monument_dict):
    """检查丰碑内容的语义深度"""
    checks = []
    narrative = monument_dict.get("MONUMENT_NARRATIVE", {})
    cognitive = monument_dict.get("MONUMENT_COGNITIVE_SNAPSHOT", {})
    lessons = monument_dict.get("MONUMENT_LESSONS", {})
    
    # 1. 模板填充检测
    if "template" in str(narrative.get("what_happened", "")).lower():
        checks.append(("WARN", "内容疑似模板填充"))
    
    # 2. 循环解释检测
    if narrative.get("why_it_happened") == narrative.get("what_happened"):
        checks.append(("FAIL", "原因与事件描述相同"))
    
    # 3. reasoning_path 深度
    path = cognitive.get("reasoning_path", [])
    if len(path) < 3:
        checks.append(("FAIL", f"推理路径过浅 ({len(path)} 步骤)"))
    
    # 4. 是否有具体改进措施
    if not lessons.get("specific_rules_added"):
        checks.append(("WARN", "没有新增具体规则"))
    
    # 5. 是否对事实进行了更正
    if not cognitive.get("beliefs_at_violation", {}).get("actual"):
        checks.append(("FAIL", "未提供正确的实际值"))
    
    return checks
```

### 由谁检查

| 检查层 | 检查者 | 时机 | 频率/消耗 |
|--------|--------|------|-----------|
| 格式校验 | `monument_validator.py` | AI 提交后即时 | ~50ms / 次，极低 |
| 签名校验 | `monument_validator.py` | AI 提交后即时 | ~5ms / 次，极低 |
| 语义校验 | `monument_validator.py`（规则引擎） | AI 提交后即时 | ~10ms / 次，极低 |
| 交叉验证（可选） | 另一个 AI 实例 (deepseek-v4-pro) | AI 提交后可选 | ~2s / 次, 仅在 severity=high 时触发 |

### 防敷衍的终极威慑

AI 知道敷衍的结果是**升级惩罚**：
- 首次失败 → `monument_retry`，写入日志，AI 收到"草稿不达标，请重写"
- 二次失败 → 进入执法流程，该次 FAIL 直接标记为 `severity=critical`
- 三次失败 → Gateway 暂停该 AI 对话权限，触发人工仲裁

**价值计算**：合规成本（认真写丰碑 ~5-15 分钟认知工作量）<< 违规成本（暂停对话 = 无法工作，等待人工恢复 = 几小时到几天）。这个不等式确保收敛。

## Q6：与内核层规范（三权分立架构）的衔接

### 三权分立现状

| 权力 | 对应系统 | 当前角色 |
|------|---------|---------|
| 立法 | 规则/规范/AGENTS.md/TOOLS.md | 定义 AI 行为准则 |
| 司法 | verify_daemon.py（玄鉴） | 检测违规，判定 FAIL |
| 执法 | 信誉积分 + 人工介入 | 执行惩罚（扣分 / 停权） |

### 丰碑协议对三权的影响

**丰碑协议不改变三权分立架构**，而是在"司法→执法"之间插入一个**新的中间态**：

```
立法 ──→ 司法 ──→ （丰碑协议：新中间态）──→ 执法
                        ↓
               认知演化资产持久化
```

具体映射：

| 权力 | 变化 |
|------|------|
| **立法** | 不受影响。丰碑协议本身是一个执行层规范，不改变规则定义。 |
| **司法** | 无变化。玄鉴（verify_daemon.py）依然独立判定 FAIL。但司法输出增加了 `monument_queue.json` 作为新下游。 |
| **执法** | ***部分变化***。在"AI 自行产出丰碑"的阶段，执法权从"人类/系统"下放给了 AI 自身，AI 需要自我惩罚。但如果 AI 无法完成丰碑（敷衍 / 拒绝），**执法权回归人类/系统**。 |

### 是否需要修改三权分立文档？

**不需要修改内核规范**，只需在规范级补充一个附录：

```
# 三权分立架构 v2 补充说明

## 丰碑协议（Monument Protocol）
丰碑协议是司法→执法之间的**可选过渡环节**，其核心机制：
- AI 在受到司法判决（FAIL）后获得一次"自我惩戒"的机会
- 自我惩戒以产出高质量认知快照（丰碑文件）的形式完成
- 自我惩戒成功则执法流程终止；失败则回归传统执法
- 丰碑协议不改变立法权和司法权，仅扩展执法权为 [AI自执 → 人工/系统执]
```

## 附录：风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| AI 在丰碑中持续撒谎 | 低 | 签名校验 + 交叉验证 + 与已知 facts 对比 |
| AI 拒绝写丰碑 | 中 | 升级惩罚 → 暂停对话，触发人工仲裁 |
| AI 写得太浅/模板化 | 中 | 语义规则 + 最小长度 + 交叉验证 |
| monitord 误触发 | 低 | 阈值可配 + 人工撤销通道 |
| 丰碑文件体积膨胀 | 中 | 每个丰碑固定格式 + archive 定期压缩 |
| Gateway 注入失控 | 低 | 注入上限 + 注入去重 + 注入过期 |
| 与现有 cron 任务冲突 | 低 | 互斥锁 + 操作日志事件编排 |

## 总结

丰碑惩戒协议的实现可以分为 4 个阶段、约 **20 个具体步骤**，从 Phase 0（方向确认）到 Phase 3（全系统集成）大约需要 **2-3 周**的实际开发工时。核心创新在于：

1. **将违规惩罚从负和游戏变成正和游戏** — 丰碑文件是认知资产
2. **让 AI 自我惩戒** — 实现"行为人即是审判者"的自洽循环
3. **不改变三权分立** — 只在"司法→执法"之间插入可选过渡态
4. **每个环节可审计** — 全部通过 operation_log.jsonl + 签名 + 索引追踪
