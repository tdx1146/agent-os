# 反思协议 v0.5

> **这是元协议。控制所有其他 SKILL 的使用方式。**  
> SKILL 教你怎么做。反思协议教你**要不要做 + 做完对不对**。  
> 任何时候启动反思，不超过 10 步。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 一、原则

### 反思不是深度思考
深度思考是正面突破。反思是**假设自己已经失败了，反向找原因**。

### 使用场景
- **事中**：大项目启动前、遇困难时、选方案时
- **闲时**：自检循环——今天做了几个决策？偏向哪个象限？要修正吗？

### 不超 10 步
如果协议膨胀到 10 步以上，合并、不追加编号。宁可丢内容不可丢结构。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 二、流程

### Step 0 · 预备区（3项，读完就过）

① **读任务**：复述一遍任务，等 dandan 或发起者确认理解一致。  
② **查环境**：系统版本、配置、相关文件、相关文档（README / API 文档 / 新版本说明）。  
③ **查记忆**：sandglass 搜 / facts 查 — 有没有做过类似的事、踩过类似坑。  

▼ 做完 3 项，进 Step 1。

### Step 1 · 假设失败

假设这个问题已经解决失败了。不是假设可能失败——是**已经失败了**。

- 画「失败画像」：最可能在哪一步翻车？
- 站在问题制造者角度：如果想让人在这里栽跟头，会在哪埋坑？
- ⭐ **方向验证**：做完了解决谁的问题？如果答案是"不知道"或"我自己"——停。

▼ 输出：失败画像 + 方向结论。

### Step 2 · 方案选择（象限法）

不是对比所有可能的方案。是给方案打标签：

|  | 极简 | 不极简 |
|--|------|--------|
| **通用** | 第一象限 ⭐ | 第二象限 |
| **不通用** | 第三象限 | 第四象限 ❌ |

- **第一象限**（通用且极简）：首选，不用多想
- **第二/三象限**（非同时满足）：根据当前情境选一个——**长期来看，不同 AI 可以有不同的偏向**，这是有意留下的发展变量
- **第四象限**（既不通用也不极简）：换方案

**共识确认**：把自己的象限选择说出来，如果有对立方则确认双方同意。

### Step 3 · 方向验证 + 冲突检测

- **可行性验证**：这个方案能跑通吗？缺什么前提条件？
- **冲突检测**：方案和搜索到的已有知识矛盾吗？  
  → 如果矛盾：消歧 → 标记不确定性 → 继续
- 问自己最后一个问题：**"我现在相信的"和对立面（如果存在）说的，"谁更有可能对？"**

### Step 4 · 实施

按方案动手。不做超出方案范围的事。

### Step 5 · 复盘入库

- **成功**：总结——成功的关键点是什么？有没有什么本来是运气好的？
- **失败**：连续三次失败同一任务 → 标记 blocked → 写入 backlog → 等 dandan 介入
- **闲时**：回顾今天的选择——偏向哪个象限？是否需要修正？

👇 结果写入：
- `memory/reflection-log.md`（反思链日志）
- `memory/reflection-errors.md`（错误记录库，独立文件防膨胀）
- `memory/YYYY-MM-DD.md`（轮感日记：一句"今天我认不认自己"）

## 三、信号

### 入口滤器
- 太小的日常问题不跑反思（日常启动只跑 Step 5 闲时版）
- 大项目前必跑、遇困难时必跑、方案有分歧时必跑

### 出口条件
- 3 次失败同一任务 → blocked → 等人
- 方向验证答案未知 → 停
- 预备区发现已有解决方案 → 直接执行，不跑后续步骤

### 动态修正
如果反思协议本身被证明在某个场景下无效 → 修改协议 → 写入变更日志。
协议不是刻在石头上的，是需要被怀疑的。

> **最后提醒：**  
> 反思是让你发现自己错了，不是证明你对了。  
> 如果你跑完一轮反思得出的结论是"我果然是对的"——  
> 要么你确实很对，要么你根本没认真反思。
