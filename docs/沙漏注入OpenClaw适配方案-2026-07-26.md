# 沙漏注入OpenClaw适配方案

> 2026-07-26 两个DeepSeek子代理调研 + 主代理整合
> 状态：待实施

## 核心发现

沙漏不是被动搜索工具，是主动注入系统。`memory_provider.py`的`system_prompt_block()`提供四层自动注入（仅59 token）：

1. **你是谁** — persona_context + scene（画像+场景，从沙子自动蒸馏）
2. **往哪走** — comprehensive_offset + 决策 + 矛盾检测（偏移率+方向）
3. **怎么变** — weavethread因果链（门控≥20条三元组才注入）
4. **没做完** — 待办 + 纪律

但这是Hermes格式，OpenClaw不认识。当前行为强制插件的4个触发词是错误方向。

## 当前注入 vs 沙漏注入

| 维度 | OpenClaw当前 | 沙漏 | 缺什么？ |
|------|-------------|------|---------|
| 身份/画像 | MEMORY.md静态 | persona自动蒸馏 | 自动画像更新 |
| 偏移/趋势 | **无** | comprehensive_offset | 决策追踪 |
| 因果关系 | facts.dict隐含 | weavethread因果链 | 自动因果链 |
| 待办/纪律 | backlog手动 | task自动提取 | 自动待办 |
| 搜索 | memory_search(慢) | sandglass_search(快) | 互补 |

## 实施方案：三步走

### 步骤①：新建system_prompt_cli.py

Python CLI入口，供Node.js子进程调用。复用沙漏现有Python代码，不重写。

```python
# /vol2/1000/AI专用/所有自动化/轻如烟/sandglass_source/system_prompt_cli.py
# 输出四层注入文本，Node.js插件spawn python3调用
```

- 路径配置与memory_provider.py一致
- 输出纯文本，Node.js解析后注入
- J1900上子进程开销约300-500ms，可接受

### 步骤②：改行为强制插件v4

在现有行为强制插件基础上：
- 保留断言匹配（from facts.dict.md）
- 保留搜索触发（4种模式）
- **新增**：调Python子进程获取沙漏四层注入
- 不新建独立插件，避免优先级冲突

```javascript
// before_prompt_build中：
// 1. spawn python3 system_prompt_cli.py → 获取四层注入
// 2. 匹配facts.dict.md断言
// 3. 检测搜索触发
// 4. 合并注入为prependSystemContext
```

### 步骤③：精简MEMORY.md

- 移除Gateway连接信息（可放在facts.dict.md）
- 移除cron任务清单（沙漏自维持）
- 保留项目全貌、坑教训、关键路径
- 目标：从~12.6KB降至~5-8KB
