# 沙漏注入OpenClaw适配方案 v6 — 2026-07-26

## 一、核心架构

### 设计原则
1. **沙漏是唯一注入源** — OpenClaw `contextInjection: "never"`，workspace文件不自动注入
2. **消费侧闭环** — 记忆生产→存储→自动搜索匹配→注入约束→AI行为改变→新记忆
3. **极简注入+按需搜索** — 四层注入+prefetch三块式（~200-300 token/轮），全量信息由AI通过sandglass_search主动调取

### 注入流程
```
before_prompt_build
  ├── system_prompt_block() — 四层注入（会话启动时一次+每轮刷新）
  │   ├── Layer1: 你是谁 — persona_context + scene_context
  │   ├── Layer2: 往哪走 — comprehensive_offset + 决策 + 矛盾
  │   ├── Layer3: 怎么变 — weavethread因果链（门控≥5条）
  │   └── Layer4: 没做完 — task_pending + iron_rules
  │
  └── prefetch(query) — 每轮三块式
      ├── 块1: 搜索引导 — 画像/场景上下文
      ├── 块2: 记忆候选 — 预搜TOP3直接注入
      └── 块3: 当前状态 — 偏移率/情绪/场景/铁律
```

### 降级机制
- CLI超时（10s）→ 跳过该块，不阻塞主流程
- prefetch失败 → 只注入四层块
- 全部失败 → 注入"沙漏系统离线"身份锚点 + 写报警文件
- 报警文件5分钟内有效，超时自动清除

## 二、与沙漏官方设计的对应

| 沙漏官方接口 | OpenClaw实现 | 说明 |
|-------------|-------------|------|
| `system_prompt_block()` | `getSystemPromptBlock()` | spawn Python CLI |
| `prefetch(query)` | `getPrefetchBlock(query)` | execSync Python -c |
| `get_tool_schemas()` | MCP工具（sandglass_search等） | OpenClaw原生MCP |
| `handle_tool_call()` | MCP工具处理 | OpenClaw原生 |

## 四、踩过的坑

1. **FTS5索引不自动更新** — 直接INSERT后需手动补FTS
2. **spawn()不支持timeout** — 需手动setTimeout+kill
3. **多行prompt破坏Python -c** — 必须清理换行+截断
4. **SIGUSR1不重载插件代码** — 需完整重启Gateway
5. **contextInjection是受保护路径** — 需手动编辑openclaw.json
6. **_infer_expand_with_context不存在** — 是规划功能，当前版本不可用

## 五、Token预算

| **合计** | **~250-400** | 对比之前~14,000 token（-97%） |
