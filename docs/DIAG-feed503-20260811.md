## 一、现象（CONTRACTS 首跑红项 1）

- C-05（consumer→LMS /feed）：近 100 行 consumer.log = **失败 18 / 成功 22**（红；契约阈值 0 失败）
- BUS-05（死信队列）：近 24h **50 条**死信（红；阈值 >5）
  - 构成：`lms.feed` 明细 22 + `handler 链全部失败` 总账 25 + 其他 3
  - **同一失败事件写 2 条死信**（handler_registry 明细 + event_consumer 总账）→ 计数虚高，实际失败事件 ≈24 个
- 错误两种形态（consumer.log 实证）：
  - `HTTPError: HTTP Error 503: Service Unavailable`
  - `TimeoutError: timed out`（urllib 10s 超时与 LMS 锁等待 10s 竞态，各约一半）
- 结论：**契约红属实且正在持续产生**（12:18:19 仍在写死信），非历史遗留。

## 二、调用链与机制

```
sandglass.entry 事件（落沙，~31min/条）
  → consumer LmsFeedHandler.handle()（handlers.py:365）
      → urllib POST /feed，timeout=LMS_FEED_TIMEOUT=10s（handlers.py:470）
      → LMS api/server.py /feed handler（server.py:461）
          → scheduler.acquire_conversation(session_id)  ← 默认超时 10s（server.py:490 不传 timeout）
              → 拿不到全局 _busy_lock → 返回 False → HTTP 503「系统正在做梦，请稍后重试」
      → 503 → RuntimeError → HandlerRegistry.dispatch 异常隔离 → 写死信（handlers.py:726）
      → 无重试（handler 链路径无重试；指数退避 3 次仅存在于旧 rules 路径 event_consumer.py:488）
```

### acquire_conversation 是什么锁？
- **全局内存线程锁** `threading.Lock()`（dream_scheduler.py:139 `_busy_lock`），非文件锁、非每会话锁
- **持有时长**：做梦全程（实测 MVP 30 步 1.4~1.7s，每 ~5min 一次 main 会话）+ **feed 自身 process_turn 全程**
- 任何会话做梦 / 任何 /feed /chat /store 请求都抢同一把锁

## 三、根因（三层）

### 根因 1（直接）：consumer 侧无重试，503 即死信
- 503 语义是「请稍后重试」（LMS 明确返回），但 handler 链路径**没有重试机制**（`_dispatch_handler_chain` → `HandlerRegistry.dispatch` 单次执行，失败即写死信）
- 旧 rules 路径有指数退避 3 次（2s/4s/8s），handler 链没有 —— 架构不对称

### 根因 2（触发）：process_turn 单次耗时 ≥10s，feed 并发必有一方等锁超时
- 铁证（lms_api.log 12:18:09~19:41）：
  - 12:18:09.567 feed A 开始 process_turn（在线熵管理阶段）
  - 12:18:09.570 元更新 #7
  - 12:18:19.406 feed B `[bus] 等待做梦完成超时(10.0s)` → 503
  - 12:18:19.410 feed A 塑形完成（**耗时 ≥10s**；期间无做梦记录——锁被 feed A 自己占着）
- process_turn = 编码（CloudEmbedder 手机 Ollama bge-m3 网络调用，当前 18ms 但曾「间歇 reset」+retries=3）+ FEP 推断/学习 + 熵管理 + 目的调整 + 记忆巩固 + 检索 + 解码 + 快照；embedding 网络抖动时轻松 >10s
- 做梦冲突（CONTRACTS 笔记所述）属实但仅 1.5s 窗口，**不是主因**；主因是 feed 自堵

### 根因 3（环境异常）：双 consumer 实例并发消费
- PID 917633（00:51:25 启动）+ PID 923314（00:56:18 启动，consumer.pid 记录此实例）
- 同读 event_bus.jsonl，幂等去重（processed_ids.jsonl）存在**跨进程竞态窗口** → 同一事件双处理 → feed 并发翻倍 → 撞锁
- 成因：start_all.sh 被重复执行（00:51/00:56）；start_consumer.sh 虽有 PID 防重检查，但重复执行时未拦住（待查细节，非本任务范围）

### 计数放大（非根因但影响 SLO）
- 失败事件在 DLQ 双写（明细+总账）→ BUS-05 条数虚高近一倍
