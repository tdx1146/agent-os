## 二、方案 A 详情（唯一代码改动）

### 改动文件
`/vol2/1000/AI专用/Agent OS/iso-sand/src/handlers.py` — 仅 LmsFeedHandler 类内部

### 改动原因
503 是「请稍后重试」语义（LMS 明确返回），但 handler 链路径无重试（重试仅存在于旧 rules 路径），导致一次撞锁即永久死信。重试 2s 后做梦（1.5s）/前一 feed（≤30s）已结束，基本必成功。

### 具体改动
1. `_post_feed` 改为可感知 HTTP 503/超时异常并抛带类型标记的异常（保留原异常链）
2. `handle()` 中包裹重试循环：`retries=3`（第 1 次 + 2 次重试），等待 `2**attempt` 秒（2s/4s），第 3 次后仍失败才 raise → 死信
3. 新增模块级环境变量 `LMS_FEED_RETRIES`（默认 3，0=关闭重试，逃生门）

### 影响面
- 仅 LmsFeedHandler 一个 handler；其他 handler（glue/store、dream_complete 等）零影响
- 重试期间 handle 阻塞 ≤14s：consumer 轮询暂停 14s（3s 间隔，事件量小，可接受）；重试失败仍走既有死信路径，不新增异常路径
- 不改变对 LMS 的请求格式/字段（text/session_id/source 原样）

### 新增变量
- `LMS_FEED_RETRIES`（int，默认 3；0=关闭）—— 环境变量，不落代码常量

### 风险评估
| 项 | 评估 |
|----|------|
| 回归风险 | 低：仅重试包裹，成功路径行为不变；handlers.py 自带 quick_test 可跑 |
| 重复副作用 | 无：feed 是幂等塑形（process_turn 只喂不指挥），重试不产生重复副作用 |
| 总线阻塞 | 低：重试期间 consumer 单线程暂停 ≤14s，事件量小（sandglass ~31min/条） |
| 逃生门 | LMS_FEED_RETRIES=0 一键关重试，无需重启 consumer 即生效（handle 实时读 env） |
