## 跨文件调用链可视化方案

**不是用复杂的工具，而是在 scripts/deploy-notes/ 中生成一份交互式 HTML：**

```
# 从图谱提取调用关系
python3 << 'PYEOF'
import json
with open('knowledge-graph-deep.json') as f:
    g = json.load(f)
# 提取 calls 边
call_edges = [e for e in g['edges'] if e['type'] == 'calls']
# 生成 HTML + D3.js 力导向图
# 保存到 scripts/deploy-notes/call-graph.html
PYEOF
```

用户打开 `call-graph.html` 就能看到：
- 圆的色块 = 文件（按模块着色）
- 圆内的点 = 函数
- 有向边 = 函数调用

这是纯前端 HTML，不需要服务器，浏览器打开就行。

## 原子工作原则

1. 每阶段内子代理可并行，**但不在同一文件上并行**
2. 每个子代理任务**只能改一个模块**（要么只改 handlers/，要么只改 utils/，要么只改 static/）
3. **修改前先备份**
4. 改完后：验证 import 可加载 → 验证 API 返回 200 → 汇报
5. 跨阶段并行：A → B → C → D 串行，但 A 内部可以并行

## 保守策略

阶段 A 完成后，先验证：
- 编辑器正常（HTTP 200）
- inject 正常（发消息成功）
- 测试框架可用（pytest 跑第一个测试）
- 调用图可打开

**如果 A 出问题 → 退回 v4.2，分析原因再重来**
